# ROBOTIS OMY + LEAP Hand 텔레오퍼레이션 및 데이터 수집 파이프라인 검토

- 작성자: 신지우
- 작성일: 2026-10-08
- 하드웨어 대상: ROBOTIS OMY (6-DoF 로봇 팔) + LEAP Hand (16-DoF 다지 핸드) + PaXini PX-6AX GEN3 (8개 3축 촉각 센서)
- 목적: 모방 학습(Imitation Learning) 및 VLA($\pi_{0.5}$) 파인튜닝을 위한 고품질 다중 모달 시연(Demonstration) 데이터 수집 파이프라인 설계

## 2. 방안별 심층 분석

### 방안 1. OMY 리더암 끝단 그리퍼 트리거 제거 + 마누스 글러브 체결

#### 메커니즘
- 로봇 팔(OMY): 리더암(OMY-L100)의 6개 관절 각도를 팔로워(OMY) 6개 관절로 1:1 직접 매핑.
- 다지 핸드(LEAP): 작업자가 착용한 MANUS 글러브의 손가락 굽힘/벌림 데이터를 실시간 수신하여 LEAP Hand 16개 관절로 리타겟팅.

#### 핵심 문제점 & 해결책 (치명적 하드웨어 간섭 극복)
* **문제점**: 리더암 끝의 기존 트리거/손잡이를 마누스 글러브를 낀 손으로 직접 파지(Grip)할 경우, 손잡이를 쥐고 있는 동안에는 손가락이 구속되어 허공에서 자유롭게 손을 펴거나 복잡한 파지 동작을 시연할 수 없음.
* **해결책 (손목/전완 브라켓 체결 방식 - Wrist/Forearm Cuff Mount)**:
  - 리더암 끝단의 손잡이/트리거 파트를 완전히 분리.
  - 리더암 끝 플랜지에 **작업자의 손목 또는 전완(팔뚝) 뒷부분에 벨크로 스트랩으로 고정되는 인체공학적 브라켓**을 3D 프린팅하여 장착.
  - 작업자는 리더암을 손으로 쥘 필요 없이, 팔을 자연스럽게 움직이는 것만으로 OMY-L100이 중력 보상 상태에서 부드럽게 따라오게 됨.
  - **작업자의 손바닥과 5개 손가락은 완전히 허공에 자유롭게 노출**되므로, 마누스 글러브를 착용한 상태에서 어떤 제약도 없이 미세한 파지/조작 동작을 수행 가능.

#### 장점
1. **IK 연산 및 특이점(Singularity) 완전 배제**: 6-DoF OMY 리더와 팔로워가 물리적으로 동일한 기구학을 가지므로, 관절 공간 1:1 매핑으로 기구학적 특이점, 관절 급회전(Joint Flip), 도달 불가 영역 문제가 100% 발생하지 않음.
2. **초저지연(Sub-5ms)**: 리더 관절각을 ROS 2 `ros2_control` 토픽으로 직결하여 즉각적이고 안정적인 제어 가능.
3. **피로도 최소화**: 리더암의 실시간 중력 보상(Gravity Compensation) 덕분에 장시간 데이터 수집 시에도 팔을 허공에 들고 있을 필요가 없어 피로도가 매우 적음.

### 방안 2. 마누스 글러브로 손 제어 + 손 6D Pose 추출 후 IK 기반 OMY 제어

#### 메커니즘
- 작업자가 허공에서 마누스 글러브를 착용하고 팔을 움직임.
- 글러브(또는 손목에 부착된 6D 트래커)로부터 손목의 3차원 위치(X, Y, Z)와 자세(Roll, Pitch, Yaw)를 측정.
- IK(Inverse Kinematics) 솔버(Pink, TRAC-IK, KDL 등)를 실행하여 OMY의 6개 관절 각도를 실시간 계산하여 전송.

#### 치명적인 한계점 & 주의사항
1. **6-DoF 로봇 팔의 IK 한계 (특이점 및 조인트 점프)**:
   - 7-DoF 로봇 팔(Franka 등)은 널스페이스(Null-space) 여유 자유도가 있어 팔꿈치를 회전시키며 특이점을 유연하게 회피할 수 있음.
   - 하지만 **OMY는 6-DoF 팔**이므로 위치 3차원 + 자세 3차원이 정확히 구속됨.
   - 손목을 조금만 비틀거나 특정 자세에 도달하면 손목 특이점(Wrist Singularity) 또는 숄더 특이점에 걸려 **로봇 관절 속도가 포화(Saturation)되거나 순식간에 180도 회전(Joint Flip)하는 위험한 현상**이 빈번하게 발생함.
2. **작업 공간(Workspace) 불일치 및 드리프트**:
   - 인간 팔의 도달 반경과 OMY(반경 약 600~700mm)의 작업 반경이 상이함.
   - 물리적 지지대나 경계가 없으므로 작업자가 무의식중에 로봇의 물리적 한계를 벗어나는 자세를 취하게 되며, 수시로 클러치(Clutch/페달)를 밟아 재정렬(Re-centering)해야 하므로 데이터 연속성이 저하됨.
3. **추가 6D 트래커 필요**:
   - 마누스 글러브 자체는 IMU 기반 손가락 각도 및 손목 회전(Orientation)만 제공하며, 절대적인 3D 공간 위치(X, Y, Z)를 측정하지 못함.
   - 손목에 HTC Vive Tracker나 OptiTrack 마커를 별도로 달아야 하며, 센서 융합 및 캘리브레이션 오차가 누적됨.

### 방안 3. 기타 선행 연구들의 대안적 접근 방식

#### 3-A. SpaceMouse + 마누스 글러브 (WHIRL / DexPilot 스타일)
* 왼손은 3Dconnexion SpaceMouse로 팔의 6차원 EE 속도를 제어하고, 오른손은 마누스 글러브로 LEAP Hand를 제어.
* 장점: 공간을 적게 차지하고 책상에 앉아서 편하게 제어 가능.
* 단점: 팔과 손의 움직임이 비대칭(Asymmetric)적이어서 작업자의 숙련도가 매우 많이 요구되며, 직관적인 고속 반응 조작이 어려움.

#### 3-B. 비전 기반 무장구 텔레오퍼레이션 (AnyTeleop / DexCap / Vision Pro)
* RGB-D 카메라 또는 VR 헤드셋의 핸드 트래킹을 이용해 맨손으로 LEAP Hand 제어.
* 장점: 글러브를 착용할 필요가 없어 장비 비용과 착용 번거로움이 없음.
* 단점: 손가락이 서로 겹치거나 주먹을 쥘 때 시각적 오클루전(Self-occlusion)으로 인해 트래킹이 튀며, 지연시간이 30~60ms 수준으로 길어 정밀한 접촉 조작 데이터 수집에 부적합.

#### 3-C. 퍼핏/미니 마스터 핸드 (GELLO 스타일)
* 리더암 끝에 실제 LEAP Hand와 구조가 흡사한 소형 엔코더 마스터 핸드를 제작하여 부착.
* 장점: 손까지도 Joint-to-Joint 완전 무지연 제어가 가능.
* 단점: 16개 관절을 갖춘 마스터 핸드를 직접 CAD 설계/제작/와이어링해야 하므로 초기 제작 공수가 매우 큼.

## 3. 손 리타겟팅(Retargeting) 최적 구성 (MANUS → LEAP Hand)

인간의 5지 관절 구조와 LEAP Hand의 4지(엄지 + 검지/중지/약지) 16-DoF 구조 간의 맵핑 전략:

1. **검지 / 중지 / 약지 (Index, Middle, Ring)**:
   - **아핀 관절 매핑 (Affine Joint Mapping)** 적용.
   - 인간 손가락의 MCP 회전/굴곡, PIP, DIP 각도를 LEAP Hand의 4개 관절 모터 범위로 선형 비례 스케일링.
   - 계산 비용이 0에 가까워 즉각적인 반응(120Hz+) 보장.
2. **엄지 (Thumb)**:
   - 엄지는 대립(Opposition) 및 파지력 형성에 가장 중요하며, 인간 엄지(안장 관절)와 LEAP 엄지의 기구학적 차이가 큼.
   - **4-DoF 손가락 끝 IK (Fingertip IK / DexRetargeting)** 방식을 엄지 파트에만 부분 적용하여, 인간 엄지 끝과 검지 끝의 상대적 거리/방향이 LEAP Hand에서도 완벽히 일치하도록 제어.

## 4. 데이터 수집 & 동기화 파이프라인 아키텍처

```
[ 하드웨어 입력 스트림 ]
  ├── 1. OMY-L100 리더암 (6 DoF q, qdot)               ─[ 100~400Hz (ROS 2) ]──┐
  ├── 2. MANUS 글러브 (Hand skeleton / angles)          ─[ 120Hz (SDK / ZMQ) ]─┤
  ├── 3. LEAP Hand 팔로워 (16 DoF q, qdot, torque)     ─[ 100Hz (Dynamixel) ]──┼─▶ [ 동기화 로거 (Synchronizer) ]
  ├── 4. PaXini PX-6AX (8센서 3축 힘/Taxel)             ─[ 100Hz (Serial) ]────┤   (Timestamp Alignment)
  └── 5. 카메라 (손목 RealSense D405 + 상부 RGB-D)      ─[ 30Hz (OpenCV/ROS) ]─┘
                                                                                      │
                                                                                      ▼
                                                                           [ LeRobot / HDF5 저장 ]
                                                                           (State, Action, Tactile, Images)
```

1. **타임스탬프 동기화**:
   - 카메라 프레임(30Hz)을 기준으로 직전/직후의 100Hz 모터 상태 및 촉각 센서 데이터를 선형 보간(Linear interpolation)하여 정렬.
2. **저장 포맷**:
   - Hugging Face `LeRobot` 및 OpenPI 공식 지원 포맷(HDF5 / Zarr)으로 에피소드 단위 직렬화.
