User PC: `jiwoo-950QDB`, Ubuntu 22.04 + ROS 2 Humble. 로봇·zenoh 없이 Manus 노드와 `leap_teleop`을 같은 PC, 기본 RMW로 돌렸다.
절차는 [`../manus_teleop_guide.html`](../manus_teleop_guide.html) (같은 내용 `../manus_teleop_guide.md`).

## 셋업에서 막힌 것 (가이드에 반영)

| 증상 | 원인 / 조치 |
|---|---|
| pytest `No module named '_pytest.scope'` | `~/.local` anyio 플러그인 vs apt pytest 6.x. `-p no:anyio` (`PYTEST_ADDOPTS`) |
| Manus 빌드 `ncursesw/ncurses.h` | `sudo apt install libncurses-dev` |
| `dynamixel_sdk` import 시 `No module named 'serial'` | `sudo apt install python3-serial` (pytest는 하드웨어 없이 통과해서 못 잡음) |
| 노드가 `tcp/10.42.0.241:7447` 접속 실패 → `bad_alloc` | 같은 셸에 zenoh 변수가 남음. `leap_env`가 `LEAP_NO_ZENOH`일 때 `RMW_IMPLEMENTATION`·`ZENOH_CONFIG_OVERRIDE`·`ROS_DOMAIN_ID`를 지우도록 수정 |
| `Resource busy` + `No license found … Integrated` | MANUS Core Dashboard가 동글을 잡고 있었음. Dashboard를 끄면 해결. Dashboard에 붙는 local 모드(`-p connection_type:=local`)를 노드에 추가했지만 Linux Dashboard는 SDK 연결을 받지 않음 |

## 엄지 리타게팅 변경

1. **15번(`thumb_ip_flex`)이 안 굽음.** 끝 + IP 점(`ip_weight` 0.3) IK에서 15번이 거의 일자로 남았다. `ip_weight` 1.0은 효과 없음(되돌림).
   → `thumb_ik.ip_joint: affine`: 15번은 글러브 `ThumbIPStretch` 비율을 그대로 쓰고, IK는 12~14번만 푼다. 실물에서 같이 굽는 것 확인.
2. **15번이 일자보다 뒤로 안 감.** affine 비율이 `[0, 1]`로 잘려서. 사람 엄지 IP는 젖혀지고 글러브도 편 손(−3.6°)보다 낮은 −12.9°까지 나왔다.
   → `thumb_ip_extend_max_deg: 20.0`: 15번만 음수 비율 허용, 최대 −20°. **다음 시험에서 확인.**

pinch 정확도는 15번 고정 때문에 조금 손해볼 수 있다. 다음에 `ip_joint: ik`와 비교한다.

## 검지 끊김 (미해결)

`/manus_glove_0`을 8초씩 두 번 기록했다. 수신은 정상(120 Hz, 최대 간격 14 ms, 멈춘 값 없음).
두 번째 기록에서 `IndexPIPStretch`가 **0~1°에 붙어 있었고**, 같은 동안 `IndexMCPStretch` 3~55°, `IndexDIPStretch` 13~31°는 움직였다. 첫 기록에서는 PIP가 0~115°로 정상.
PIP가 0이면 LEAP 검지 가운데 마디가 펴진 채로 남아 끊기는 것처럼 보인다. 그 순간 실제로 PIP를 굽혔는지는 확인 못 함.

다음에 할 것: 재착용 → `ros2 topic echo`로 PIP 확인 → 그래도면 Dashboard에서 글러브 캘리브레이션 (그 뒤 Dashboard 끄기) → 계속되면 "PIP=0이고 MCP가 굽었으면 MCP 비율을 빌림" 보정 검토.
