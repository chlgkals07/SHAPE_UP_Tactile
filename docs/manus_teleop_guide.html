안전 수칙 (매 단계)

  • LEAP 5V를 즉시 끊을 수단을 손 닿는 곳에 둔다. 이상하면 5V를 먼저 끊고 Ctrl+C.
  • 5V는 항상 손을 편 상태에서 켠다. 모터가 회전수를 누적해서, 접힌 채 켜면 다음 전원 투입 때 영점이 360° 어긋난다.
  • 시험 중 손가락 주변에 손·케이블을 두지 않는다. LEAP Hand v1(16모터) 전용이다.
  • omy_ai는 launch 즉시 팔이 움직인다. 작업 공간을 비우고 비상 정지 수단을 확인한다.
  • 팔이 움직이는 동안 손은 주먹으로 둔다. (leap_* 함수는 --safe-pose fist가 기본)
  • 텔레옵 중에는 leader를 반드시 손으로 잡는다. 10/09에 leader가 갑자기 크게 튄 적이 있다.

  • LEAP을 플랜지에서 오른쪽 90° 돌려 달고, follower joint6을 +π/2 돌려서 home에서 손가락이 위를 향한다.
  • home 단계에서 손목이 왼쪽으로 90° 돈다. home·ready의 joint6 = π/2 (ready = [0, −90°, 152°, −62°, 90°, 90°]).
  • leader 기준으로 joint6은 +90° ~ −180°까지 돈다. leader가 켜질 때 leader 손목을 0 근처로 잡는다.
  • 원리: leader broadcaster가 leader 위치 + offsets를 보내므로 joint6 offset만 π/2로 둔다. Homing Offset·순정 파일·모터 설정은 바꾸지 않았다. 코드: OMY_Tactile_Robot_PC/omy_leap_bringup.
  • joint6만 π 돌리는 방식은 쓰지 않는다. follower joint6 모터 한계가 ±π라 한쪽으로 못 돈다.
  • D405는 link6 몸통에 붙어 있어서 90°만 돌아 손 옆에 온다.
녹화하면 joint6이 π/2 근처다. 순정 장착 데이터와 한 데이터셋에 섞지 않는다. leader self-collision 검사는 offset 전 각도와 그리퍼 모델로 판단한다. 11/12에는 막힌 적이 없지만 정확하지 않다.

오늘은 환경 확인용이다. 팔 + zenoh + LEAP 경로가 살아 있는지 본 뒤 3단계로 간다.

leader 트리거 값 입력 (쥔 상태는 아직 미측정)

편 상태와 쥔 상태에서 7번째 값을 읽어 user_pc/config/leader_gripper.yaml의 open_value / closed_value에 넣는다. 지금은 임시값 0.0 / 1.0이고, 편 상태 실측은 약 0.197이다.

전환

2단계 정리, 3단계 준비

3단계(Manus 단독)는 팔이 필요 없다. 아래 순서로 끄고 새로 시작한다.

  1. User PC: leap_leader 셸에서 Ctrl+C (Torque OFF).
  2. Robot PC 터미널 B: omy_ai Ctrl+C — 팔이 처질 수 있으니 손으로 받친다.
  3. Robot PC 터미널 A: zenohd Ctrl+C.
  4. LEAP 5V를 편 손으로 껐다 켠다 (모터 회전수 누적 초기화).

엄지 방식 (11/03 수정)

관절방식설정
12·13·14번IK: 엄지 끝 + IP 관절 위치를 맞춘다thumb_ik.ip_weight: 0.3
15번 (엄지 맨 위 관절)글러브 ThumbIPStretch를 그대로 따른다 (affine). 끝만 맞추는 IK에서는 15번이 거의 안 굽었다 실측 11/03thumb_ik.ip_joint: affine (예전 방식은 ik)

안 맞을 때

  • 손가락 방향이 반대 → manus_leap.yaml의 side_gain 또는 joint_map
  • 엄지가 이상함 → --thumb affine으로 대응표부터 맞춘 뒤 IK
  • 엄지 맨 위 관절이 덜/더 젖혀짐 → thumb_ip_extend_max_deg
  • pinch 틈이 큼 → 15번 고정 때문일 수 있다. ip_joint: ik와 비교
  • 검지가 끊김 실측 11/12 해결: 글러브 IndexPIPStretch가 0에 붙던 것. 원인은 Manus SDK 캘리브레이션 누락이었다 (“글러브 캘리브레이션” ①). Dashboard 캘리브레이션은 integrated 모드에 적용되지 않는다.
  • 엄지가 안 펴짐 / 엄지 맨 위 관절이 튐 11/12 미해결: SDK 캘리브레이션 뒤 ThumbCMCStretch 범위가 5°로 줄었다. 글러브를 충전하고 SDK 캘리브레이션(.mcal 저장) → leap_glovecal --force → leap_manus --log-csv logs/run_ik.csv로 다시 본다.
  • 빠르게 움직이면 LEAP이 최대 0.5초 늦다 (속도 제한 120°/s). 250~300°/s로 올리는 것을 검토 중이다.
  • IK에서 손끝 틈이 남음 → pinch snap 추가 검토 (spec 7절)
  • pinch 결과는 docs/field-test/에 10/09 형식으로 남긴다

사건이 뚜렷한 에피소드를 따로 찍어 스트림끼리 몇 ms 어긋나는지 잰다.

오류가 어디서 났는지 남는지

검증용 임시 단계. 검증되면 가이드에서 빠진다. 여기서 본 실제 로그 줄로 hub.yaml의 devices.leap.events 정규식을 맞춘다.

일부러 안전한 오류를 내서 홈 화면, 사고 폴더, 로그 화면이 제대로 남기는지 본다.

① LEAP 모터 응답 없음 (5V 끈 채로)

  1. LEAP 5V를 끈 상태로 텔레옵을 dry-run 해제해서 켠다 (5V 확인 항목은 이 시험에서만 그냥 체크한다. 모터에 전원이 없으니 움직이지 않는다). 연결 단계에서 Missing or unresponsive DYNAMIXEL IDs: [...]로 끝나야 한다.
  2. 홈의 LEAP 칸이 빨개지고 "모터 응답 없음: 0, 1, …"처럼 번호가 나오는지. 장치 상세 모터 표의 해당 칸이 빨간지.
  3. 로그 페이지에 사고가 하나 생기고, 30초 뒤 leap_manus.log, others/가 채워지는지. zip 받기.
  4. 5V를 켜고 5분 안에 LEAP 모터 확인을 돌리면 그 사고 폴더에 leap_check.txt가 붙는지.

② USB 빠짐

  1. 손목 카메라 USB를 뺀다 → 사건 "손목 카메라 USB (D405) 없음", "USB 빠짐: …". 다시 꽂으면 "다시 잡힘".

③ 텔레옵 중 끊김 (실제로 생길 때)

  • 텔레옵 중 특정 모터가 빠지면 [leap] feedback read failed: … 줄이 주의로 남는다 (1초에 한 번). 그때 홈의 문제 줄 → LEAP 모터 확인 버튼으로 바로 확인한다.
  • 로그에 찍힌 실제 문구가 정규식에 안 걸리면(홈에 안 뜨면) 그 줄을 복사해 두고 devices.leap.events를 고친다 → 설정 다시 읽기.
사고 폴더 위치: ~/.local/state/control_hub/sessions/<세션>/incidents/<시각_장치_내용>/ (summary.md, checks.json, 프로세스 로그, others/, leap_check.txt). 같은 장치에서 30초 안에 난 오류는 한 폴더에 모인다.
