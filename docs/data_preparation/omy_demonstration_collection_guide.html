00 · 경로 선택

이 문서의 수집 경로

ROBOTIS는 새 모방학습 작업에 Cyclo Intelligence를 권장합니다. 이전 Physical AI Tools는 레거시 경로입니다. 여기서는 OMY 텔레오퍼레이션으로 시연하고 Cyclo Intelligence의 Record와 Data Tools를 사용합니다.

01 · 연결리더·팔로워, USER PC, 카메라
02 · 실행Zenoh, 로봇, 카메라 노드
03 · 수집토픽 확인 후 rosbag2 에피소드
04 · 정리재생·선별·LeRobot 변환
사용 전 가정실제 장비 프로파일은 OMY-F3M 팔로워와 OMY-L100 리더이며, USER PC는 Linux와 Docker를 사용합니다. 제품 구성이나 소프트웨어 버전이 다르면 기종별 설정 및 토픽 이름을 먼저 확인하세요.

02 · 로봇과 통신

Zenoh를 올린 뒤 텔레오퍼레이션

  1. 로봇과 USER PC를 같은 접근 가능한 네트워크에 둡니다. OMY 전원을 켜고 본체 일련번호에 따른 호스트 이름 또는 실제 IP를 확인합니다. ROBOTIS 예시는 omy-SNPR44B9999.local입니다.
  2. ROBOT PC의 OpenMANIPULATOR 컨테이너에 들어갑니다. 초기 설정이 필요한 장비는 공식 Setup Guide의 하드웨어·전원·unpacking 절차를 먼저 완료합니다.
  3. Zenoh 데몬을 시작합니다. 네트워크에 최소 하나가 실행되어야 ROS 2 노드들이 서로 발견됩니다. 권장 위치는 로봇 측 컨테이너입니다.
  4. 로봇 작업영역을 비우고 리더·팔로워 launch를 시작합니다. 이 명령은 팔로워를 초기 위치로 움직이고, 리더 중력 보상을 시작한 다음 두 팔을 동기화합니다.
ROBOT PC 호스트 · SSH 및 컨테이너 진입 예시
ssh root@omy-SNPR44B9999.local
cd /data/docker/open_manipulator
./docker/container.sh start
./docker/container.sh enter

호스트 이름은 실제 일련번호로 바꾸세요. 설치된 로봇 이미지와 계정 구성이 다르면 해당 장비의 접속 정보를 따릅니다.

ROBOT PC · OpenMANIPULATOR 컨테이너 · 터미널 A
zenohd
ROBOT PC · 같은 컨테이너의 별도 터미널 B
ros2 launch open_manipulator_bringup omy_ai.launch.py
즉시 움직일 수 있음omy_ai.launch.py 실행 시 팔로워가 바로 움직일 수 있습니다. 주변 사람·물체를 치우고 비상 정지 수단을 확인한 뒤 시작하세요. 리더·팔로워 조작 중에 추론용 팔로워 bringup을 동시에 실행하지 마세요.

USER PC의 Zenoh 연결

카메라 노드를 실행할 USER PC의 OpenMANIPULATOR 컨테이너를 로봇 측 Zenoh 데몬에 클라이언트로 연결합니다. IP 예시 192.168.0.42를 실제 ROBOT PC 주소로 바꾸세요. 모든 관련 터미널·컨테이너에서 ROS_DOMAIN_ID를 일치시킵니다.

USER PC · OpenMANIPULATOR 컨테이너
export ZENOH_CONFIG_OVERRIDE='transport/shared_memory/enabled=true;mode="client";connect/endpoints=["tcp/192.168.0.42:7447"]'
export RMW_IMPLEMENTATION=rmw_zenoh_cpp
echo $ROS_DOMAIN_ID
ros2 topic list

Cyclo Manager로 시작하는 경우에는 System 화면에서 Zenoh Daemon을 먼저 켜고 OMY 프로파일의 Robot Bringup을 시작합니다. 이 문서의 터미널 절차와 별도의 실행 경로이므로 같은 로봇 스택을 중복 실행하지 않습니다.

03 · 카메라

카메라 노드와 기록 설정을 연결

표준 OMY 구성에서 카메라는 USER PC에 연결됩니다. OMY의 Camera 포트를 USB-C ↔ USB-A 케이블로 USER PC에 연결하고, USER PC의 OpenMANIPULATOR 컨테이너 안에서 카메라 노드를 실행합니다.

USER PC · OpenMANIPULATOR 컨테이너 · 손목 RealSense 한 대만 연결했을 때
ros2 launch realsense2_camera rs_launch.py camera_name:='cam_wrist'

D435i 두 대를 함께 연결하면 일련번호가 없는 이 기본 명령은 의도하지 않은 카메라를 선택할 수 있습니다. 세 대를 동시에 쓸 때는 아래 D435i 두 대 추가 절차처럼 손목 카메라까지 일련번호로 고정하세요.

영상 토픽이 네트워크에 보이는지 확인하세요. Cyclo Intelligence Record 화면의 Camera Views에서 실제 화면을 보고, Topic Monitor에서 토픽 수신과 측정 Hz를 확인합니다.

카메라 노드가 있는 컨테이너 · 토픽 확인
ros2 topic list
# 위 목록에서 실제 영상 토픽을 찾은 뒤 실행
ros2 topic hz <actual_image_topic>

카메라 네임스페이스와 압축 토픽의 실제 이름은 장치 설정에 따라 달라집니다. <actual_image_topic>을 실제 발행 토픽으로 바꾸세요.

추가 카메라가 있을 때

ROBOTIS 문서는 ZED2 및 USB 카메라도 허용합니다. 추가 뷰는 카메라 노드 실행과 로봇 설정 파일의 기록 대상 등록이 둘 다 필요합니다. Cyclo Intelligence는 로봇 설정 파일에 적힌 토픽만 기록합니다. 아래는 일반 예시이며, 이어지는 D435i 두 대 전용 절차에서는 실제 OMY-F3M 설정 파일을 기준으로 설명합니다.

USER PC · Cyclo Intelligence 호스트 · 설정 파일 찾기
cd ~/cyclo_intelligence/shared/shared/robot_configs
ls
nano <your_robot>_config.yaml
설정 예시 · 실제 토픽으로 교체
observation:
  images:
    camera1:
      topic: /camera1/image_raw/compressed
      msg_type: sensor_msgs/msg/CompressedImage
    camera2:
      topic: /camera2/image_raw/compressed
      msg_type: sensor_msgs/msg/CompressedImage
      rotation_deg: 270

camera2는 변환 데이터셋의 observation 키가 됩니다. rotation_deg는 선택 사항이며 허용 값은 0, 90, 180, 270입니다. USB 장치의 /dev/videoN 번호는 재연결 때 바뀔 수 있으므로 매번 확인합니다.

USER PC · 추가 카메라 장치와 노드 예시
v4l2-ctl --list-devices
ros2 run usb_cam usb_cam_node_exe --ros-args --remap __node:=camera2 -p video_device:=/dev/video6 -r image_raw:=camera2/image_raw -r image_raw/compressed:=camera2/image_raw/compressed -r camera_info:=camera2/camera_info
# RealSense를 추가한다면 위 USB 명령 대신:
ros2 launch realsense2_camera rs_launch.py camera_name:=camera2

03B · 추가 카메라 실습

D435i 두 대를 USER PC에 연결하기

아래 예시는 OMY 손목 카메라를 유지하고, 작업대 정면의 D435i를 cam_front, 측면의 D435i를 cam_side로 추가합니다. 두 D435i 모두 OMY의 Camera 포트가 아닌 USER PC의 USB 3 포트에 직접 연결합니다.

실행 순서이 절의 1 → 2 → 3 → 4를 순서대로 진행합니다. 3번을 시작하기 전에는 앞의 02절에서 로봇 측 Zenoh 데몬을 켜고 USER PC의 OpenMANIPULATOR 컨테이너가 그 데몬에 연결되도록 설정해야 합니다. 이후 04절에서 Cyclo Intelligence를 설치·실행하고 이 절의 5 → 6 → 7을 마칩니다. 이미 Cyclo가 설치되어 있다면 04절 설치 부분은 건너뛸 수 있습니다.
물리 장치USB 연결ROS 이름Cyclo 관측 키
OMY 손목 카메라OMY Camera 포트 → USER PCcam_wristcam_wrist
D435i #1 · 정면/상단 고정USB-C ↔ USB 3 포트 Acam_frontcam_front
D435i #2 · 측면 고정USB-C ↔ USB 3 포트 Bcam_sidecam_side

1. 기계·USB 배치

  1. 정면 카메라는 작업대와 목표 위치가 한 화면에 들어오게, 측면 카메라는 그리퍼의 접근·파지와 물체 높이가 보이게 단단히 고정합니다. 고정 후 카메라 위치가 바뀌면 새 데이터 수집 세션으로 관리합니다.
  2. 각 D435i를 품질이 좋은 짧은 USB 3 케이블로 USER PC에 연결합니다. 가능하면 서로 독립적인 USB 3 포트/컨트롤러를 사용하고, 허브가 필요하면 외부 전원이 있는 USB 3 허브를 사용합니다. PC의 포트 두 개가 내부적으로 같은 허브를 공유할 수 있습니다.
  3. 카메라와 케이블에 front/side 라벨을 붙이고, 관절·그리퍼 이동 범위와 접촉하지 않도록 고정합니다. USB 연결만으로 두 카메라가 하드웨어 동기화되는 것은 아닙니다.

RealSense 다중 카메라 가이드는 직접 연결이 높은 대역폭에서 유리하고, USB 전원·케이블 품질·호스트 처리 능력도 프레임 손실에 영향을 준다고 설명합니다. 이 구성에서는 우선 자유 실행 카메라의 타임스탬프로 기록을 시작하고, 깊이 프레임의 엄밀한 하드웨어 동기가 필요한 별도 연구에서는 RealSense 동기화 가이드를 적용하세요.

2. 세 카메라의 일련번호와 USB 3 연결 확인

USER PC 호스트에서 손목 카메라와 추가 D435i 두 대를 한 대씩 연결해 물리 위치와 일련번호를 대응시킵니다. rs-enumerate-devices가 설치되어 있으면 각 장치의 Serial Number와 USB Type Descriptor가 보여야 합니다. lsusb -t에서 D435i 두 장치의 SuperSpeed 경로도 확인합니다.

USER PC 호스트 · 장치 식별
rs-enumerate-devices -S
lsusb -t
세 대의 일련번호 대응표를 남기세요예: 손목 SN 111111111111, 정면 SN 123456789012, 측면 SN 987654321098. 이 숫자는 모두 설명용입니다. 실제 기기의 일련번호로 바꾸지 않으면 아래 launch가 연결되지 않습니다. USB 장치 번호(/dev/videoN)보다 일련번호를 기준으로 고정하면 재연결 시 카메라 이름이 뒤바뀌는 일을 막을 수 있습니다.

카메라를 USER PC의 OpenMANIPULATOR 컨테이너에서 실행하므로 그 안에서도 두 장치가 보여야 합니다. ROBOTIS의 OpenMANIPULATOR 컨테이너 설정은 /dev:/dev를 매핑하지만, 실제 설치본의 장치 접근 권한과 매핑을 확인합니다. 호스트에서 보이고 컨테이너에서 보이지 않으면 카메라 노드를 시작하기 전에 컨테이너 장치 매핑·권한을 수정합니다.

USER PC · OpenMANIPULATOR 컨테이너 · 장치/패키지 확인
rs-enumerate-devices -S
ros2 pkg prefix realsense2_camera
ros2 pkg prefix compressed_image_transport

rs-enumerate-devices가 없다면 librealsense 유틸리티의 설치 상태를 확인하세요. compressed_image_transport가 없다면 압축 영상 토픽이 나오지 않을 수 있습니다. 카메라가 실제로 연결된 USER PC의 OpenMANIPULATOR 이미지에 해당 ROS 패키지를 설치·유지해야 합니다.

3. 카메라별 노드 실행 · 터미널 세 개

USER PC의 OpenMANIPULATOR 컨테이너에서 앞서 설정한 Zenoh 연결 환경을 적용하고, 손목·정면·측면 카메라에 서로 다른 터미널을 사용합니다. 기존의 일련번호 없는 손목 카메라 노드가 실행 중이면 먼저 종료합니다. serial_no에는 ROS 2 숫자 문자열 처리 때문에 RealSense 문서대로 일련번호 앞에 밑줄(_)을 붙입니다. 세 노드는 기본 camera 네임스페이스를 공유하지만 이름은 각각 달라야 합니다.

USER PC · OpenMANIPULATOR 컨테이너 · 터미널 B · 손목 카메라
# 111111111111을 손목 카메라의 실제 SN으로 교체
ros2 launch realsense2_camera rs_launch.py \
  camera_namespace:=camera camera_name:=cam_wrist \
  serial_no:=_111111111111
USER PC · OpenMANIPULATOR 컨테이너 · 터미널 C · 정면 D435i
# 123456789012를 정면 카메라의 실제 SN으로 교체
ros2 launch realsense2_camera rs_launch.py \
  camera_namespace:=camera camera_name:=cam_front \
  serial_no:=_123456789012 \
  enable_color:=true enable_depth:=true \
  rgb_camera.color_profile:=640x480x30 \
  depth_module.depth_profile:=640x480x30
USER PC · OpenMANIPULATOR 컨테이너 · 터미널 D · 측면 D435i
# 987654321098을 측면 카메라의 실제 SN으로 교체
ros2 launch realsense2_camera rs_launch.py \
  camera_namespace:=camera camera_name:=cam_side \
  serial_no:=_987654321098 \
  enable_color:=true enable_depth:=true \
  rgb_camera.color_profile:=640x480x30 \
  depth_module.depth_profile:=640x480x30

640×480 @ 30 Hz는 세 카메라를 함께 시험하기 위한 시작값입니다. 해당 D435i가 이 RGB·깊이 프로필을 지원하는지 rs-enumerate-devices와 launch 로그로 확인하세요. 프레임이 떨어지면 해상도·FPS·USB 구성을 조정합니다. 깊이 데이터가 전혀 필요하지 않다면 enable_depth:=false로 바꿔 USB와 CPU 부하를 줄일 수 있습니다. IMU는 기본적으로 비활성이고 이 VLA 영상 경로에 필요하지 않습니다.

4. ROS 토픽 세 쌍을 확인

다음 경로는 기본 camera 네임스페이스와 위 이름을 사용했을 때의 기대 형태입니다. RealSense ROS wrapper 버전에 따라 RGB 기본 토픽이 image_raw 또는 image_rect_raw일 수 있으므로, 실제로 발행되는 /compressed 토픽을 확인해 다음 YAML에 그대로 적어야 합니다.

USER PC · OpenMANIPULATOR 컨테이너 · 토픽 확인
ros2 node list | grep -E 'cam_wrist|cam_front|cam_side'
ros2 topic list -t | grep -E 'cam_(wrist|front|side).*(color|depth|camera_info)'
# 실제 압축 RGB 토픽으로 아래 예시를 수정해서 측정
ros2 topic hz /camera/cam_front/color/image_raw/compressed
ros2 topic hz /camera/cam_side/color/image_raw/compressed

기대하는 깊이 토픽 형태는 /camera/cam_front/depth/image_rect_raw와 /camera/cam_side/depth/image_rect_raw이며 메시지 형식은 보통 sensor_msgs/msg/Image입니다. RGB 압축 토픽은 sensor_msgs/msg/CompressedImage여야 합니다. 토픽 이름·형식·실제 Hz를 ros2 topic list -t, ros2 topic info, Cyclo의 Topic Monitor에서 재확인하세요.

USER PC · 토픽 형식 점검 예시
ros2 topic info /camera/cam_front/color/image_raw/compressed
ros2 topic info /camera/cam_side/color/image_raw/compressed
ros2 topic info /camera/cam_front/depth/image_rect_raw
ros2 topic info /camera/cam_side/depth/image_rect_raw

5. OMY-F3M 수집 설정에 RGB 뷰 두 개 등록

먼저 아래 04절의 Cyclo Intelligence 설치를 완료합니다. USER PC 호스트의 ~/cyclo_intelligence/shared/shared/robot_configs/omy_f3m_config.yaml을 복사해 백업한 뒤 수정합니다. 실제 파일의 최상위 구조는 orchestrator → ros__parameters → omy_f3m이며, 기존 cam_wrist와 관절·행동 항목은 유지합니다. 아래는 observation.images와 recording.extra_topics만 발췌한 예시입니다.

USER PC 호스트 · OMY-F3M 설정 백업과 편집
cd ~/cyclo_intelligence/shared/shared/robot_configs
cp omy_f3m_config.yaml omy_f3m_config.yaml.bak
nano omy_f3m_config.yaml
YAML 발췌 · 실제 압축 토픽을 확인해 적용
orchestrator:
  ros__parameters:
    omy_f3m:
      observation:
        images:
          cam_wrist:
            topic: /camera/cam_wrist/color/image_rect_raw/compressed
            msg_type: sensor_msgs/msg/CompressedImage
          cam_front:
            topic: /camera/cam_front/color/image_raw/compressed
            msg_type: sensor_msgs/msg/CompressedImage
          cam_side:
            topic: /camera/cam_side/color/image_raw/compressed
            msg_type: sensor_msgs/msg/CompressedImage
      recording:
        extra_topics:
          - /tf
          - /camera/cam_wrist/color/camera_info
          - /camera/cam_front/color/camera_info
          - /camera/cam_side/color/camera_info
YAML 전체를 위 발췌본으로 덮어쓰지 마세요기존 파일의 observation.state, action, urdf_path를 반드시 보존합니다. cam_front/cam_side의 토픽이 시스템에서 image_rect_raw/compressed로 발행된다면 그 경로로 바꿉니다. camera_info도 실제 토픽을 확인해 넣으세요. ROBOTIS 설정 코드가 이를 카메라별 보정 스냅샷으로 연결합니다.

설정 변경 뒤 Cyclo Intelligence를 다시 시작하거나 로봇 유형을 다시 선택해 설정을 재읽도록 합니다. Home에서 OMY F3M을 선택하고 Record → Camera Views에 손목·정면·측면 세 화면이 모두 나타나는지 확인합니다. 첫 세 영상의 배치 순서는 YAML 입력 순서를 따르므로 위치가 헷갈리면 카메라 이름과 실제 장면을 함께 확인하세요.

6. 깊이 데이터의 저장 범위 결정

Depth 카메라 ≠ Depth 학습 데이터 자동 생성현재 ROBOTIS Cyclo Intelligence 설정 코드에서 LeRobot 변환·웹 영상 파이프라인이 지원하는 observation.images 형식은 sensor_msgs/msg/CompressedImage입니다. D435i의 원본 깊이 sensor_msgs/msg/Image 토픽을 observation.images에 넣어도 정상적인 깊이 VLA 관측으로 자동 변환된다고 볼 수 없습니다. 위 설정으로 수집되는 학습용 세 뷰는 RGB 영상입니다.

깊이 원본도 향후 연구를 위해 에피소드와 함께 보존하려면, 코드 스키마상 recording.extra_topics에 아래 두 원본 깊이 토픽을 추가해 MCAP 보조 토픽으로 기록할 수 있습니다. 이는 Cyclo 공식 문서의 기본 RGB 워크플로를 확장하는 방법이므로, 짧은 시험 에피소드 후 MCAP 안에 깊이 메시지가 실제로 들어갔는지 반드시 검사하세요. LeRobot 변환 결과에는 별도 변환 코드가 없는 한 깊이 관측이 생기지 않습니다.

선택 사항 · 기존 recording.extra_topics 목록에 추가
          - /camera/cam_front/depth/image_rect_raw
          - /camera/cam_front/depth/camera_info
          - /camera/cam_side/depth/image_rect_raw
          - /camera/cam_side/depth/camera_info
USER PC · Cyclo Intelligence 컨테이너 · 시험 MCAP 확인
# 아래 경로를 실제 데이터셋 이름과 에피소드 번호로 교체
ros2 bag info /workspace/rosbag2/<dataset_name>/<episode_index>/

ros2 bag info에 두 깊이 토픽과 0보다 큰 메시지 수가 표시되는지 확인합니다. 기록 결과가 없다면 Cyclo 서비스를 재시작하고 설정 파일 경로, 발행 토픽, Topic Monitor를 다시 확인하세요.

깊이 보존을 택하면 저장 용량이 크게 늘어납니다. 색·깊이의 픽셀 단위 정렬이 필요하면 RealSense의 align_depth.enable, 동일 카메라 내 프레임 결합이 필요하면 enable_sync를 검토하고 실제 출력 토픽과 타임스탬프를 별도로 검증하세요. 두 카메라 사이의 정밀 하드웨어 동기는 별도 배선·설정이 필요한 고급 구성입니다.

06 · 시연 녹화

하나의 시도 = 하나의 에피소드

  1. Home에서 로봇 유형을 선택합니다. 목록에는 cyclo_intelligence/shared/shared/robot_configs에 설정 파일이 있는 유형만 표시됩니다.
  2. Record로 이동해 Camera Views와 Topic Monitor를 다시 확인합니다. 화면이 비거나 토픽 수신이 없으면 녹화를 시작하지 않습니다.
  3. Rosbag Recorder에 Task Num, Task Name, Task Instruction을 입력합니다. 예: “검은 컵을 집어 재활용 상자에 넣어라”. 일반 기록은 Add License를 체크하지 않습니다.
  4. 세부 단계 레이블이 필요 없으면 Number of SubTasks = 0으로 둡니다. 단계별 지시가 필요하면 시작 전에 개수를 정하고 각 Sub Task Instruction을 입력합니다.
  5. 물체와 팔을 시작 자세에 놓고 Record Start를 누릅니다. 리더를 움직여 성공 시연을 수행한 뒤 Save Episode로 저장합니다. 실패하거나 잘못 기록한 시도는 Discard Episode를 누릅니다.
  6. 다음 시도 전 시작 조건을 재설정하고 반복합니다. 서브태스크를 사용하면 정한 단계 수를 모두 저장해야 에피소드가 완료됩니다.
입력 필드의미권장 입력 방식
Task Num데이터셋 작업 번호/식별자작업별로 고정해 관리
Task Name짧은 작업명한 작업에 일관된 이름 사용
Task Instruction시연 전체의 자연어 지시대상·동작·목적지를 명확히 기술
Number of SubTasks단계별 레이블 수단일 연속 시연이면 0
Sub Task Instruction각 단계의 자연어 지시서브태스크가 있을 때만 입력
서브태스크 개수는 녹화 전에 결정예를 들어 “접근 → 잡기 → 놓기”를 각 단계로 레이블하려면 3을 입력하고 각 단계를 순서대로 저장합니다. 단일 에피소드에 하나의 전체 지시만 필요하면 0이 단순합니다.

저장 위치와 파일

원본 rosbag2 데이터는 Cyclo Intelligence 컨테이너의 /workspace/rosbag2/<dataset_name>/<episode_index>/에 저장됩니다. 호스트에서는 $HOME/cyclo_intelligence/docker/workspace/rosbag2/...에서 찾습니다.

07 · 데이터 마감

검수 → 정리 → LeRobot 변환

  1. Review Episodes: Select Task에서 /workspace/rosbag2의 작업 폴더를 선택하고 각 에피소드를 재생합니다. 카메라 뷰, 3D 뷰, 관절 데이터, 지시문, 타임라인을 확인합니다.
  2. Delete Episodes: 실패 동작, 누락된 영상, 잘못된 지시문 등 사용할 수 없는 에피소드의 인덱스를 기록해 삭제합니다. 남은 인덱스를 0..N-1로 다시 매기려면 Compact indices after delete를 켭니다. 삭제 전 원본 백업을 권장합니다.
  3. Merge Rosbag Datasets: 같은 작업을 여러 폴더에 나눠 녹화했다면 필요한 경우 합칩니다. 결과는 /workspace/rosbag2에 생성됩니다.
  4. Convert Dataset: 검수한 작업을 선택하고 실제 카메라 발행 속도에 맞춰 목표 FPS를 정한 뒤 LeRobot v2.1, v3.0 또는 둘 다 선택합니다. 결과는 /workspace/lerobot에 저장됩니다.
  5. 외부 학습 환경으로 전달: 필요한 경우 Data Tools의 Hugging Face 업로드 기능으로 변환 데이터셋을 전송합니다. 업로드 권한과 공개 범위는 사용 중인 계정·프로젝트 정책에 맞춰 결정합니다.
FPS 기준15 Hz 카메라면 15 FPS, 30 Hz면 30 또는 용량을 줄인 15 FPS가 문서의 예시입니다. 카메라별 속도가 다르면 가장 느린 카메라를 기준으로 합니다. 변환은 실제로 없는 프레임을 만들어내지 못합니다.

Cyclo Data는 MCAP에서 관측과 행동을 목표 FPS에 맞춰 정렬하고, 카메라 타임스탬프로 대응 MP4 프레임을 선택합니다. 변환 완료 후 짧은 에피소드 몇 개를 다시 재생해 영상·행동 정렬과 지시문을 확인하세요.

품질 관리

증상먼저 확인할 것조치
ROS 2 토픽이 보이지 않음Zenoh 데몬, 실제 로봇 IP, 7447 연결, ROS_DOMAIN_ID로봇 측 데몬 실행 → USER PC의 ZENOH_CONFIG_OVERRIDE 수정 → ros2 daemon stop 후 재확인
토픽은 보이나 값이 안 옴컨테이너 네트워크 구성과 RMW, 카메라/로봇 노드 로그ros2 topic echo /joint_states와 Camera Views로 실제 메시지 흐름 확인
카메라 화면이 비어 있음USB 연결, 카메라 노드, 실제 이미지 토픽장치 재인식 후 토픽 이름과 로봇 설정 파일의 이름을 일치
D435i가 한 대만 보임호스트·컨테이너의 rs-enumerate-devices -S, USB 3 링크, 전원각 카메라를 단독으로 시험하고 포트·짧은 케이블·전원 공급 허브를 바꿔 비교
정면/측면 영상이 뒤바뀜각 노드의 serial_no와 실제 기기 SN일련번호 대응표를 수정하고 카메라 노드를 재시작
압축 RGB 토픽이 없음compressed_image_transport, 실제 image_raw/image_rect_raw 경로USER PC 카메라 컨테이너의 플러그인 설치와 발행 토픽 확인
녹화했는데 영상이 빠짐선택 로봇 config의 observation.images, Record의 Topic Monitor설정에 발행 중인 토픽을 등록하고 짧은 시험 에피소드 재수집
깊이가 LeRobot 결과에 없음Cyclo의 압축 RGB 변환 지원 범위원본 깊이 토픽은 보조 MCAP으로 보존하고 별도 변환 파이프라인 설계
변환 FPS가 맞지 않음각 영상 토픽의 실제 측정 Hz가장 느린 카메라 이하로 목표 FPS 설정
예상하지 못한 팔 움직임조작을 중지하고 주변을 확보합니다. 리더·팔로워 제어와 추론용 팔로워 bringup이 중복 실행 중인지 확인한 뒤, 안전한 상태에서 하나의 제어 경로만 재시작하세요.
